# Indoor map data schema (v0)

Shared contract between the map data pipeline (`mapdata/`) and the web app (`indoor-nav/`).
IMDF-inspired, but authored in a **local metric frame** so the positioning engine and routing work in metres.

## Coordinate frame

- Units: **metres**. `[x, y]` positions, `x` → right on the 1F drawing, `y` → up on the 1F drawing (y flipped from SVG/EMF).
- Origin: south-west (bottom-left) corner of the 1F **main enclosure** (outer wall faces). Outdoor platforms, ramps and porches outside it have negative coordinates (west entrance platform reaches x ≈ −14 m, porches y ≈ −3.1 … 69.2 m) — that's expected.
- All floors share this frame (2F is registered to 1F via the structural column grid).
- The web app converts local metres to WGS84 for MapLibre using `venue.json` → `origin` (lng/lat of local (0,0)) and `bearing_deg` (clockwise angle from true north to local +y). Until the building is georeferenced, any origin near the site works.

## Files (per venue directory, e.g. `data/tianmu/`)

```
venue.json
levels/<level_id>/walls.geojson     LineString  — drawing linework for rendering + wall constraints
levels/<level_id>/units.geojson     Polygon     — rooms / areas (the "beautified" map is a style over these)
levels/<level_id>/pois.geojson      Point       — amenities & openings
nav.geojson                         Point nodes + LineString edges (all levels)
```

GeoJSON files are FeatureCollections whose coordinates are local metres (not WGS84).

### venue.json
```json
{
  "id": "tianmu",
  "name": "臺北市立大學天母體育館",
  "name_en": "UTaipei Tianmu Gymnasium",
  "origin": { "lng": 121.5335, "lat": 25.1155 },
  "bearing_deg": 0,
  "levels": [
    { "id": "1F", "ordinal": 0, "name": "1F", "elevation_m": 0 },
    { "id": "2F", "ordinal": 1, "name": "2F", "elevation_m": 5.0 }
  ],
  "default_level": "1F"
}
```

### walls.geojson — LineString
| prop | values |
|---|---|
| `layer` | `wall` \| `column` \| `stairs` \| `fixture` \| `court` \| `door` \| `other` |

### walls3d.geojson — Polygon / MultiPolygon (optional, for the 2.5D map)
Generated by `tools/walls3d.py` from walls.geojson: each wall segment becomes a 0.2 m thick quad (merged per source
line into a MultiPolygon); columns are their closed squares. Door openings remain gaps. Props: `layer` = `wall` | `column`.
All features are extruded to **one uniform height chosen by the app** — the goal is visible partitions and a 3D feel,
not real storey heights.

### seating3d.geojson — Polygon (optional, 2.5D stepped stands; currently 2F)
Generated by `tools/seating3d.py` from `seating` units: rows parallel to the court edge (≈0.9 m deep), each a solid
step `height_m = 0.5 × row`, plus a 1.1 m `parapet` strip at the court edge. Props: `kind` (`tier` | `parapet`),
`section` (north/south/west/east), `row`, `height_m`, `base_m`. Unlike walls, these use **per-feature heights**.
(`walls3d.py` skips seating-row linework inside stands so it doesn't extrude as tall walls.)

| prop | type | notes |
|---|---|---|

| `ref` | string? | room number on signage, e.g. `A101` |
| `name` | string? | Chinese display name |
| `name_en` | string? | |
| `accessible` | bool? | wheelchair accessible |

| prop | type | notes |
|---|---|---|

### Optional props (v0 additions — consumers must tolerate unknown props)
- `venue.json` → `georeferenced: false` while `origin` / `bearing_deg` are approximate.
- units → `ref_verified: false` when the signage ref (A1xx) was matched by position only, not read off a sign.
- pois → `accessible_verified: false` when step-free access is assumed but not checked on site; `capacity`, `speed` on elevators.
- Scope (accessibility-first): 1F and 2F both have units / POIs / nav (2F from the 2F directory sign); floors connect via elevators #1/#2 (accessible) and stairs A–D (not). Seating units carry `section` (north/south/east/west).

### nav.geojson
- Node: `Point`, props `{ "kind": "node", "id": "1F-n12", "level": "1F" }`
- Edge: `LineString` (2 points: from → to), props
  `{ "kind": "edge", "from": "1F-n12", "to": "1F-n13", "type": "corridor" | "door" | "stairs" | "elevator" | "ramp", "accessible": true, "length_m": 4.2 }`
- Edges are undirected. Cross-level edges (`stairs`, `elevator`) connect nodes on different levels; their geometry is the 2D segment, `length_m` includes a vertical cost (elevator: fixed 15 m equivalent, stairs: 2× climb).
- `accessible: false` for stairs and steps; the "accessible route" option only uses `accessible: true` edges.
